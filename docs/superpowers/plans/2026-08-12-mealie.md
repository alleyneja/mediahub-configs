# Mealie Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Mealie with a PostgreSQL backend at `https://mealie.lan`, authenticated by Authentik OIDC, so Jay and Mafe share one recipe collection, meal plan, and shopping list.

**Architecture:** Two containers (`mealie`, `mealie-postgres`) on the `mediahub_internal` network, repo-managed at `~/mediahub-configs/stacks/mealie/`, with no published host ports. Caddy terminates TLS at `mealie.lan` using its internal CA. All persistent state lives on the NVMe under `/srv/docker/mealie/`.

**Tech Stack:** Docker Compose, `ghcr.io/mealie-recipes/mealie:v3.22.0`, `postgres:16-alpine`, Caddy 2, Authentik 2024.12.3.

**Spec:** `docs/superpowers/specs/2026-08-12-mealie-design.md`

## Testing note

This is infrastructure, not application code — there is no unit test suite. The TDD
cycle is preserved in its infrastructure form:

1. Write the verification command
2. Run it and confirm it **fails** (proving the check is real and not vacuous)
3. Make the change
4. Run it again and confirm it **passes**
5. Commit

A verification step that was never seen failing is not evidence. Do not skip step 2.

## Global Constraints

- **Image pinned to `v3.22.0`.** Never `:latest`. Bumps are deliberate and scoped (no-blanket-auto-update policy).
- **No persistent state on `/mnt/media` or the NAS.** The mergerfs pool runs `cache.files=off`, which blocks `mmap`; NFS has weak locking/`fsync`. Databases live on NVMe only.
- **`mediahub-configs` is a PUBLIC repo.** No credentials in tracked files. Secrets go in `mealie.env` / `.env`, covered by the `*.env` gitignore rule.
- **No published host ports.** Access via Caddy only.
- **Never use `extra_hosts` to pin `auth.lan`.** Use `dns: ${SERVER_IP}`. Caddy's container IP is not stable — Calibre-Web is currently broken this way.
- **`REQUESTS_CA_BUNDLE` is forbidden in this stack.** It replaces Python's trust store and would break public-site recipe scraping. Use `OIDC_TLS_CACERTFILE`.
- **`ALLOW_PASSWORD_LOGIN` stays `true`** permanently.
- **Both live and mirror must be edited** for Caddy (`/srv/docker/caddy/Caddyfile`) and Homepage (`/srv/docker/homepage/config/*.yaml`). The repo copies are mirrors, not the live files.
- **Commit to `mediahub-configs` before the session ends** (standing rule). Do not `git push` without asking.

- [ ] **Step 4: Write the compose file**

Create `/home/jay/mediahub-configs/stacks/mealie/docker-compose.yml`:

```yaml
services:
  mealie-postgres:
    image: postgres:16-alpine
    container_name: mealie-postgres
    environment:
      POSTGRES_USER: mealie
      POSTGRES_DB: mealie
      TZ: America/Chicago
    env_file:
      - mealie.env
    volumes:
      # NVMe only. The mergerfs pool cannot mmap (cache.files=off) and NFS
      # has weak locking/fsync — both corrupt Postgres.
      # See docs/mergerfs-cache-files-off.md.
      - /srv/docker/mealie/pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U mealie -d mealie"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - mediahub_internal
    restart: unless-stopped

  mealie:
    image: ghcr.io/mealie-recipes/mealie:v3.22.0
    container_name: mealie
    depends_on:
      mealie-postgres:
        condition: service_healthy
    # AdGuard, so the container can resolve auth.lan through Caddy.
    # Do NOT use extra_hosts — Caddy's container IP is not stable.
    dns:
      - ${SERVER_IP}
    environment:
      TZ: America/Chicago
      PUID: 1000
      PGID: 1000
      BASE_URL: https://mealie.lan
      ALLOW_SIGNUP: "false"
      # Keep the local admin door open alongside SSO, permanently.
      ALLOW_PASSWORD_LOGIN: "true"
      DB_ENGINE: postgres
      POSTGRES_SERVER: mealie-postgres
      POSTGRES_PORT: 5432
      POSTGRES_USER: mealie
      POSTGRES_DB: mealie
    env_file:
      - mealie.env
    volumes:
      - /srv/docker/mealie/data:/app/data
    networks:
      - mediahub_internal
    restart: unless-stopped

networks:
  mediahub_internal:
    external: true
```

Expected: `1`.

- [ ] **Step 3: Add the CA mount and OIDC variables to the compose file**

In the `mealie` service, add to `volumes:`:

```yaml
      # OIDC only — see OIDC_TLS_CACERTFILE below.
      - /srv/docker/caddy/caddy-root.crt:/etc/ssl/certs/caddy-root.crt:ro
```

And add to `environment:`:

```yaml
      OIDC_AUTH_ENABLED: "true"
      OIDC_CONFIGURATION_URL: https://auth.lan/application/o/mealie/.well-known/openid-configuration
      OIDC_PROVIDER_NAME: Authentik
      OIDC_USER_GROUP: mealie-users
      OIDC_ADMIN_GROUP: admin
      OIDC_GROUPS_CLAIM: groups
      OIDC_SIGNUP_ENABLED: "true"
      OIDC_REQUIRES_EMAIL_VERIFICATION: "false"
      # Scoped to the OIDC client only. Do NOT use REQUESTS_CA_BUNDLE — it
      # REPLACES Python's trust store, which would leave this container
      # trusting only Caddy and silently break recipe URL scraping from
      # public sites. See docs/calibre-web-ca-bundle.md.
      OIDC_TLS_CACERTFILE: /etc/ssl/certs/caddy-root.crt
```

- [ ] **Step 4: Recreate the container**

```bash

sleep 20
docker logs mealie 2>&1 | tail -30
```

Expected: no OIDC-related errors on startup.

**5c. Both login paths work**, in the browser at `https://mealie.lan`:
